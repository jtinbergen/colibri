# Packet: Slice 10-ext — per-machine combination matrix

Deliverable: the base plan §10 matrix as a per-machine grid, not a single
global table. Promotion is per-machine.

## 1. Scope and invariants

- Axes: MSA × expert-tasks × planner (off / shadow-only / active);
  contexts: short / long; residency: limited / high.
- Per-machine axis where applicable: NUMA / island choice; out-of-scope
  routes (`S>1`, spec, URING, GPU execution on A) tested for fallback
  only.
- Out-of-scope routes must take the legacy path; assert byte-equal
  outputs.
- ABI-relevant kernel changes still require the existing GLM / Segment
  / Edge gates; this slice does not waive them.

## 2. Tasks

1. Define the matrix as JSON: rows = configurations, columns = machines
   (A / B / C / D), cells = `(status, artifact path)`. Each cell is one
   slice run; an absent machine cell is `NOT_RUN`.
2. Run smoke + fixed replay + free generation + stress + profiling for
   every supported cell.
3. Cross-reference each cell to its gate report. Cells with `INCONCLUSIVE`
   remain opt-in.
4. Promote only tested configurations; record the per-machine baseline
   and promotion row.

## 3. Evidence

- Matrix JSON at `docs/results/m3-execution-slice-10-ext-matrix-<date>.json`.
- Per-machine summary report.

Artifact: `docs/results/m3-execution-slice-10-ext-<date>.md`.

## 4. Gate 10-ext

- C: all required regression and combined lifecycle cases green.
- M: each intended route demonstrably active; fallback documented; no
  duplicate schedulers or unbounded nested pools.
- P: pre-registered per-machine thresholds. No global tok/s claim.
